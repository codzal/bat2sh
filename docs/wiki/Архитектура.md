## Модель вывода (PC-dispatch)
Программа нумеруется по инструкциям; каждая попадает в `case $PC`:
```bash
PC=0
dispatch() { case $PC in
  0) ...; PC=1 ;;
  1) ...; PC=2 ;;
esac }
while [ "$PC" -ge 0 ]; do dispatch; done
exit $ERRORLEVEL
```
`goto X` = `PC=N; return`. **Вызываемые** метки (не являющиеся целью goto)
становятся bash-функциями `sub_*`: обычный вызов не бросает цикл `while`,
в отличие от PC-прыжка. Вокруг вызова сохраняется/восстанавливается `ARGS`.

## Пайплайн строки
`translate_segment`: strip/@ → nul-замена → rem/:: → goto → reg/sc →
self._cmd dict → WIN_COMMAND_MAP → пользовательские правила (config) →
passthrough (`expand_vars`) с инкрементом fallback-статистики.

## Раскрытие переменных (`shell.expand_vars`, lru_cache)
Порядок важен: `%VAR:f=r%` → `%VAR:~s,l%` → `%~dpN` → `%*`/аргументы →
`%errorlevel%` → `%VAR%` (с dot-sanitize и WIN_ENV) → `%%` → `!…!`-формы.
Замена `f=r` эскейпится glob-классами без обратного слэша, чтобы не ломалась
в `dos_slashes`; для loop-переменных используется runtime-хелпер `ci_replace`.

## for /f
`read -ra _arr` c `IFS=<delims>`; rest-переменные считаются из исходной строки
через `_anchor/_pre/_incl` (сохраняет внутренние разделители);
`delims=` (пусто) отключает разбиение; `tokens=*` — trim всей строки.

## Точки расширения
* новый флаг CLI → `_argparser()` (+ обработка в `main`/`_process_job`)
* новая команда → метод `cmd_*` + запись в `Translator._cmd` или WIN_COMMAND_MAP
* рантайм-хелпер → блок в `extras` (как REG_FUNCS/ci_helper) по флагу need_*
